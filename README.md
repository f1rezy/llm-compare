# LLM Compare

## О продукте

LLM Compare — приложение для сравнения ответов языковых моделей на один запрос. Цель проекта — дать пользователю возможность оценивать ответы разных моделей в одном интерфейсе.

Frontend отвечает за интерфейс, backend выступает в роли BFF для работы с внешним API моделей, а пакет common содержит общие контракты и HTTP-утилиты.

Реализованы получение списка моделей и параллельная генерация ответов через AI Proxy.
Пользователь может добавлять и удалять колонки, выбирать модели и отправлять им общий запрос.
Каждая колонка независимо показывает загрузку, ответ или ошибку. После ошибки можно повторить
запрос только для одной колонки, сохранив остальные ответы.

Ответы отображаются в Markdown с поддержкой таблиц и блоков кода через `react-markdown`
и `remark-gfm`. Под ответом показываются время ожидания, оценка стоимости и доступные счётчики токенов.
Интерфейс построен по принципу mobile-first, стили компонентов организованы через CSS Modules.

### Поведение интерфейса

- В сравнении от двух до четырёх колонок. Чтобы добавить колонку, нажмите «Добавить модель» и выберите модель из списка.
- На экранах уже 768 px между колонками можно переключаться вкладками. От 768 px ответы расположены рядом, а шапки колонок с названием модели и провайдером закреплены при прокрутке ответов.
- От 768 px у нижнего края области ответов появляется градиент, если ниже ещё есть содержимое. В конце прокрутки он исчезает.
- Пока есть активные запросы, ввод и отправка нового общего запроса заблокированы.
- Смена модели очищает результат колонки и отменяет ожидание её текущего запроса.
- Удаление колонки отменяет ожидание её ответа. При двух колонках удаление недоступно.
- Новая колонка участвует в следующей отправке общего запроса.
- Новый общий запрос заменяет предыдущий запрос и ответы; история диалога не сохраняется.
- Frontend измеряет время до первого фрагмента и до завершения ответа. Оба показателя включают сеть и работу BFF.
- После завершения запросов самый быстрый ответ отмечается, если успешно ответили хотя бы две модели. При одинаковом времени отметку получают все колонки с минимальным временем.
- После завершения запросов самый дешёвый ответ отмечается, если есть хотя бы две оценки стоимости. При равенстве отметку получают все колонки с минимальной оценкой.
- Счётчики токенов, которые провайдер не вернул, не отображаются; нулевые значения сохраняются.

Каждая колонка читает свой поток `/api/stream` и показывает Markdown по мере получения текста.
Время и счётчики токенов отображаются после события `finish`. При закрытии потокового
соединения BFF отменяет свой запрос к AI Proxy. Для получения ответа целиком доступен
маршрут `/api/generate`.

## Структура проекта

Монорепозиторий организован с помощью npm workspaces:

| Пакет        | Назначение                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **common**   | Общие контракты API, типы `PingApi`, `ModelsApi` и `GenerateApi`, утилиты `fetchJSON` и `fetchResponse` для frontend. Подключается как исходники TypeScript. |
| **backend**  | HTTP-сервер на встроенном `node:http`, маршрутизация, JSON-ответы, обработка ошибок и логирование через Pino. TypeScript запускается через `tsx`.            |
| **frontend** | SPA на React и TypeScript. Vite используется для разработки и сборки.                                                                                        |

Основные директории:

| Путь                    | Содержимое                                                   |
| ----------------------- | ------------------------------------------------------------ |
| `common/src/types/`     | Контракты запросов и ответов API                             |
| `common/src/utils/`     | Общие HTTP-утилиты                                           |
| `backend/src/config/`   | Пути маршрутов                                               |
| `backend/src/routes/`   | Обработчики запросов                                         |
| `backend/src/services/` | Взаимодействие с AI Proxy                                    |
| `backend/src/pkg/`      | Отправка JSON, CORS, логгер, конфигурация окружения и ошибки |
| `backend/src/index.ts`  | Создание HTTP-сервера, запуск и завершение работы            |
| `frontend/src/`         | Компоненты React, стили и точка входа                        |
| `frontend/src/api/`     | Запросы frontend к BFF                                       |
| `frontend/src/hooks/`   | Загрузка моделей и управление генерацией по колонкам         |
| `frontend/src/ui/`      | Компоненты интерфейса и CSS Modules                          |
| `.husky/`               | Git-хуки для проверок перед коммитом                         |

## Локальный запуск

### Требования

- Node.js 24.x или новее. Для Node.js 22 требуется версия не ниже 22.13.0.
- npm с поддержкой workspaces.

### Установка зависимостей

Из корня репозитория:

```bash
npm ci
```

Команда устанавливает зависимости всех трёх пакетов из общего `package-lock.json` и настраивает Git-хуки Husky.

### Переменные окружения

Перед первым запуском создай файл настроек backend:

```bash
cp backend/.env.example backend/.env
```

Если `.env` уже существует, сохрани его настройки вместо повторного копирования.

| Переменная             | Назначение                                                | По умолчанию  |
| ---------------------- | --------------------------------------------------------- | ------------- |
| `PORT`                 | Порт HTTP-сервера                                         | `3001`        |
| `NODE_ENV`             | `development`, `production` или `test`                    | `development` |
| `AI_API_URL`           | Базовый URL AI Proxy без `/models` или `/generate`        | Обязательная  |
| `AI_API_AUTHORIZATION` | API-ключ для заголовка `x-api-key`, без префикса `Bearer` | Обязательная  |
| `AI_API_TIMEOUT_MS`    | Таймаут запроса к AI Proxy, мс                            | `120000`      |

Укажи `AI_API_URL=http://llm.codex.so` и заполни `AI_API_AUTHORIZATION` ключом, полученным от администратора сервиса.

Backend загружает `.env` через параметр Node.js `--env-file`. Класс `BackendEnv` в `backend/src/pkg/env.ts` проверяет настройки при запуске и сохраняет их для дальнейшего использования. При отсутствии обязательных переменных или некорректных значениях сервер не запускается.

При `NODE_ENV=test` автоматический запуск сервера и логирование отключены. Проверка конфигурации сохраняется: для тестов необходимо задавать URL и фиктивный ключ до первого вызова `BackendEnv.getInstance()`.

Файл `.env` исключён из Git. Реальные ключи доступа не должны попадать в `.env.example` или frontend.

### Запуск приложений

В двух терминалах из корня репозитория:

```bash
# Терминал 1 — backend с перезапуском при изменениях
npm run dev:backend
```

```bash
# Терминал 2 — frontend
npm run dev:frontend
```

Backend по умолчанию доступен на `http://localhost:3001`. Адрес frontend выводится в терминале Vite; стандартный порт — `5173`, при занятости порта Vite может выбрать следующий.

В режиме разработки Vite перенаправляет запросы `/api` на `http://localhost:3001`.
Если меняешь порт backend, обнови также `server.proxy` в `frontend/vite.config.ts`.

## API backend

### Проверка доступности

```bash
curl http://localhost:3001/api/ping
```

Ответ с кодом `200`:

```json
{
    "success": true,
    "data": {
        "message": "pong"
    }
}
```

Неизвестный маршрут возвращает `404` и объект `{ "success": false, "error": "Not found" }`. При внутренней ошибке до отправки заголовков сервер возвращает `500` с общим сообщением, а подробности записывает в лог. Если ответ уже начат, соединение закрывается.

### Получение списка моделей

```bash
curl -i http://localhost:3001/api/models
```

Backend обращается к `GET /models` [AI Proxy](https://github.com/codex-team/ai-proxy), передавая API-ключ в заголовке `x-api-key`. Ключ остаётся на backend.

Пример ответа с кодом `200`:

```json
{
    "success": true,
    "data": {
        "default": "example/model",
        "models": [
            {
                "id": "example/model",
                "name": "Example model",
                "pricing": {
                    "input": 1,
                    "output": 2,
                    "cacheRead": 0.1
                }
            }
        ]
    }
}
```

Пример иллюстрирует формат: список моделей и цены приходят из AI Proxy. `default` содержит ID модели по умолчанию. Цены указаны в USD за миллион токенов; поле `cacheWrite` необязательно.

При ошибке возвращается `{ "success": false, "error": "..." }`:

| Статус | Причина                                                                     |
| ------ | --------------------------------------------------------------------------- |
| `429`  | Превышен лимит запросов к AI Proxy                                          |
| `502`  | Ошибка сети, неуспешный ответ AI Proxy (кроме `429`) или ошибка чтения JSON |
| `504`  | Истёк таймаут запроса, включая чтение тела ответа                           |
| `500`  | Неожиданная внутренняя ошибка                                               |

### Генерация ответа

`POST /api/generate` генерирует ответ одной модели. Для сравнения frontend отправляет
отдельный запрос на каждую колонку, в том числе если в нескольких колонках выбрана одна модель.

Получив ID из `/api/models`, подставь его вместо `example/model`:

```bash
curl -i http://localhost:3001/api/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Объясни разницу между массивом и срезом в Go","model":"example/model"}'
```

Тело запроса должно быть JSON-объектом. Поля `prompt` и `model` обязательны:
оба должны быть непустыми строками, пробелы по краям обрезаются.
Размер тела ограничен 64 КиБ. Backend передаёт запрос в `POST /generate` AI Proxy.

Пример ответа с кодом `200`:

```json
{
    "success": true,
    "data": {
        "text": "Массив имеет фиксированную длину, а срез описывает часть массива.",
        "usage": {
            "inputTokens": 12,
            "outputTokens": 34,
            "totalTokens": 46,
            "cachedInputTokens": 0
        },
        "estimatedCostUsd": 0.00008
    }
}
```

В `usage` также могут присутствовать `reasoningTokens` и `cachedInputTokens`.
Все отдельные счётчики необязательны. Время ответа не входит в контракт API:
frontend измеряет его самостоятельно.

`estimatedCostUsd` — необязательная оценка стоимости в долларах США. BFF использует тарифы
из последнего успешного ответа `/api/models` в текущем процессе. Оценка доступна, если известны
оба счётчика токенов, `cachedInputTokens` равен нулю и у модели нет отдельного тарифа на запись
в кэш. При отсутствии оценки интерфейс показывает «Недоступна».

При ошибке возвращается `{ "success": false, "error": "..." }`:

| Статус | Причина                                                                             |
| ------ | ----------------------------------------------------------------------------------- |
| `400`  | Некорректный JSON, неверные поля запроса или ответ `400` от AI Proxy                |
| `413`  | Тело запроса превышает 64 КиБ                                                       |
| `429`  | Превышен лимит запросов к AI Proxy                                                  |
| `502`  | Ошибка сети, неуспешный ответ AI Proxy (кроме `400` и `429`) или ошибка чтения JSON |
| `504`  | Истёк таймаут запроса, включая чтение тела ответа                                   |
| `500`  | Неожиданная внутренняя ошибка                                                       |

### Потоковая генерация

`POST /api/stream` принимает те же `prompt` и `model`, что и `/api/generate`.
BFF запрашивает NDJSON у AI Proxy и передаёт события клиенту по мере получения.

```bash
curl -N http://localhost:3001/api/stream \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Объясни, что такое срез в Go","model":"example/model"}'
```

Используй ID модели из `/api/models`. Успешный ответ имеет тип
`application/x-ndjson`, каждое событие занимает одну строку.

```jsonl
{"type":"text-delta","delta":"Срез "}
{"type":"text-delta","delta":"описывает часть массива."}
{"type":"finish","usage":{"inputTokens":12,"outputTokens":34,"cachedInputTokens":0},"estimatedCostUsd":0.00008}
```

`finish` завершает успешный поток. `usage` содержит доступные счётчики,
а `estimatedCostUsd` рассчитывается по тем же правилам, что и у `/api/generate`.
До начала потока ошибки возвращаются обычным JSON с полями `success` и `error`
и соответствующим HTTP-статусом. После отправки заголовков неудачный поток
заканчивается событием `{"type":"error","message":"…"}`.

### Обработка ответов

Backend проверяет входящие данные пользователя, но доверяет структуре успешного ответа AI Proxy:
отдельная валидация полей JSON внешнего сервиса не выполняется.

Утилиты `fetchJSON` и `fetchResponse` предназначены для запросов frontend к BFF и не выбрасывают исключения при HTTP-статусах ошибок. Вызывающий код проверяет `success` в JSON-ответе; сетевые ошибки и ошибки разбора JSON обрабатываются через `try/catch`. Для обращения к AI Proxy backend использует обычный `fetch` с проверкой HTTP-статуса.

## Команды

Все команды ниже выполняются из корня репозитория.

| Команда                  | Описание                                                                 |
| ------------------------ | ------------------------------------------------------------------------ |
| `npm run dev:backend`    | Запуск backend в режиме разработки                                       |
| `npm run dev:frontend`   | Запуск Vite dev server                                                   |
| `npm run build:frontend` | Проверка типов frontend и сборка в `frontend/dist`                       |
| `npm run typecheck`      | Проверка типов всех пакетов                                              |
| `npm run typecheck:ci`   | Проверка типов с записью отчётов в `typecheck-report.txt` внутри пакетов |
| `npm run lint`           | ESLint для всех пакетов                                                  |
| `npm run lint:ci`        | ESLint с записью JSON-отчётов в `eslint-report.json` внутри пакетов      |
| `npm run lint:fix`       | Автоматическое исправление поддерживаемых ESLint ошибок                  |
| `npm run format`         | Форматирование файлов проекта через Prettier                             |
| `npm run format:check`   | Проверка форматирования без изменений                                    |

Запуск backend без отслеживания изменений:

```bash
npm run start -w @llm-compare/backend
```

Backend запускается из TypeScript и требует установленных `tsx` и `pino-pretty`, которые сейчас находятся в devDependencies. Отдельная сборка backend и common не настроена.

Для просмотра собранного frontend:

```bash
npm run build:frontend
npm run preview -w @llm-compare/frontend
```

`preview` используется для локальной проверки сборки. Тестовые команды и автоматический CI пока не настроены.

## Качество кода

- **TypeScript** — проверка типов и общие контракты между пакетами.
- **ESLint и Prettier** — проверка кода и единое форматирование.
- **Husky и lint-staged** — запуск настроенных проверок для изменённых файлов перед коммитом. Конфигурации lint-staged находятся в пакетах frontend, backend и common.
- **Commitlint** — проверка сообщений коммитов по Conventional Commits.

Перед отправкой изменений выполни:

```bash
npm run lint
npm run typecheck
npm run format:check
npm run build:frontend
```

Примеры сообщений коммитов:

```text
feat(backend): добавить получение списка моделей
fix(common): исправить обработку HTTP-ошибок
docs: описать локальный запуск проекта
```

Подробнее — в [правилах оформления коммитов](COMMIT_CONVENTION.md).
